# tools/inverse — опыты по обратной задаче

Скрипты `jshell`, которыми получены все числа документа
[`theory/10-недогрев-и-идентифицируемость.md`](../../theory/10-недогрев-и-идентифицируемость.md).

Ничего в коде не меняется: скрипт собирает ту же схему, что тест `SolveTest3`
(`Boiler` → `Turbine(4)` → ПВД-2 (3.5 МПа) → ПВД-1 (2.5 МПа) → деаэратор (0.6 МПа)
→ ПНД (0.15 МПа) → конденсатор), прогоняет `StateResolver` + `FlowSystem`
и работает **внешним слоем**: подбирает параметры подогревателей так, чтобы
расчёт совпал с «измерениями» (`G0 = 9.4128 кг/с`, `G_к = 7.3557 кг/с`,
`N_э = 10 000 кВт`).

## Запуск

```bash
mvn -q -DskipTests compile

CP=target/classes:$HOME/.m2/repository/com/hummeling/if97/2.0.0/if97-2.0.0.jar:$HOME/.m2/repository/org/ojalgo/ojalgo/57.4.0/ojalgo-57.4.0.jar

jshell -q --class-path "$CP" tools/inverse/InvModel.jsh tools/inverse/exp1-solve.jsh
jshell -q --class-path "$CP" tools/inverse/InvModel.jsh tools/inverse/exp2-sensitivity.jsh tools/inverse/exp3-split.jsh
```

`InvModel.jsh` всегда первый: в нём класс `Inv` (модель и наблюдения).
`exp3-split.jsh` использует класс `Nest` из `exp2-sensitivity.jsh`, поэтому
запускается только вместе с ним и после него.

## Состав

| Файл | Что делает |
|---|---|
| `InvModel.jsh` | схема + `evaluate(eta, dt1, dt2, dt3) -> {G_к, N_э, G1, G2, G3, G4}`; невязки `res(...)`; демпфированный Ньютон `newton(eta, dt2, dt3, ...)` по конечным разностям |
| `exp1-solve.jsh` | опыт A (η_oi задан: сходимость из 5 стартов) и опыт B (η_oi = 0.82…0.88) |
| `exp2-sensitivity.jsh` | якобиан ∂(G_к, N_э)/∂(Δt₂, Δt₃) в точке решения, число обусловленности; вложенная итерация «Δt₃ из баланса массы → остаток по мощности» для η_oi = 0.80/0.83/0.85/0.87 |
| `exp3-split.jsh` | при замкнутой массе: как Δt₂ перераспределяет отборы ПВД-1/ПВД-2 (и почти не двигает N_э) |
| `out/` | протоколы прогонов (артефакты документа, не перегенерируются тестами) |

## Протоколы

| Файл | Прогон |
|---|---|
| `out/exp1-solve.txt` | `exp1-solve.jsh` целиком |
| `out/exp2-exp3-run.txt` | `exp2-sensitivity.jsh` + `exp3-split.jsh` |
| `out/protocol-newton.txt` | покомпонентный протокол Ньютона из стартов (0, 0) и (10, 10) |
| `out/legacy-analytic.txt` | **отозванная** аналитическая ветка (см. §10.11 документа): её числа не подтвердились кодом |

## Главный вывод

Итерация по недогреву сходится за 2 шага и находит `Δt₂ = 5.0023 K`, но
**только если η_oi зафиксирован**. Чувствительность наблюдений к `Δt₂`:
`∂N_э/∂Δt₂ = −1.0 кВт/K` (0.010 %/K), `∂G_к/∂Δt₂ = +0.00057 кг/с·K`; курс обмена
с η_oi — `1 K ≈ 1.1·10⁻⁴ η_oi`. Поэтому при реальной точности приборов
недогрев определяется с погрешностью ±50 K, то есть не определяется.
Подробности и таблицы — в `theory/10-...`.
